# DRP_CleansingEngine

Console App สำหรับคัดกรองสินค้าที่ไม่ควรถูกตัดยอดขาย (Keep Gate 1) ของระบบ DRP
อ้างอิงงาน **SCRUM-14 [PBI-03]** เกณฑ์คุ้มครอง Keep Gate 1

## งานนี้ทำอะไร
ระบบจะอ่านยอดความต้องการสุทธิย้อนหลัง 24 เดือนของแต่ละสินค้า (SKU) ในแต่ละคลัง แล้วตรวจว่าสินค้านั้น **ยังไม่มีข้อมูลมากพอให้ตัดยอด Outlier** หรือไม่ ถ้าเข้าเงื่อนไขข้อใดข้อหนึ่งด้านล่าง จะกำหนดเป็น **KEEP** (เก็บยอดขายเดิมไว้ทั้งหมด ไม่ตัดทอน) เพื่อป้องกันปัญหาของขาดสต็อกจากการตัดยอดผิดพลาด

| ลำดับ | เงื่อนไข | เหตุผลที่บันทึก |
|---|---|---|
| 1 | ประวัติสั้นกว่า 12 เดือน (`HistoryMonths < 12`) | `History < 12M` |
| 2 | ขายห่างๆ (`ADI > 1.32`) | `Intermittent Demand (ADI > 1.32)` |
| 3 | ยอดนิ่งสนิท (`SD = 0`) | `Zero Variance (SD = 0)` |

ถ้าไม่เข้าเงื่อนไขทั้ง 3 ข้อ จะเป็น **PENDING** (ส่งต่อไปตรวจ Gate 2 ใน PBI-04)
กรณีเข้าหลายเงื่อนไขพร้อมกัน จะบันทึกเหตุผลของข้อที่มาก่อนตามลำดับในตาราง

## สูตรที่ใช้

| สูตร | ค่าที่คำนวณ | วิธีคิด |
|---|---|---|
| FM-03 | HistoryMonths | `24 - เดือนแรกที่มียอดขาย + 1` (ไม่มียอดขายเลย = 0) |
| FM-04 | ActiveMonths | จำนวนเดือนที่ยอดขาย > 0 |
| FM-05 | ADI | `24 / ActiveMonths` (ถ้า ActiveMonths = 0 ให้ ADI = 0 กันหารศูนย์) |
| FM-06 | AvgDemand | `ยอดรวม 24 เดือน / 24` |
| FM-07 | SD | ส่วนเบี่ยงเบนมาตรฐานแบบ sample (หารด้วย 23 เทียบเท่า `STDEV.S`) |

## โครงสร้างโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `Program.cs` | จุดเริ่มโปรแกรม เชื่อมต่อฐานข้อมูล โหลดเกณฑ์ ADI และข้อมูลยอดขาย แล้วแสดงผลสรุป |
| `CleansingEngine.cs` | สูตร FM-03 ถึง FM-07 และการตัดสิน KEEP / PENDING (ไม่ยุ่งกับฐานข้อมูล) |
| `Tests.cs` | Unit Test 12 เคส (TC-03-01 ถึง TC-03-12) ตามที่ระบุใน Jira |

## ข้อมูลที่ใช้

- `AxWebReport_UAT.dbo.DRP_FCT_SKU_MONTHLY_DEMAND_PREP` ยอดความต้องการสุทธิรายเดือน (`net_demand_qty`, `month_no` 1 ถึง 24) ถ้าเดือนไหนไม่มีข้อมูล จะนับเป็น 0
- `AxWebReport_UAT.dbo.M_LOV` เกณฑ์ ADI (`LOV_CODE_1 = 'DRP_CONFIG'`, `LOV_CODE_2 = 'ADI_THRESHOLD'`) ถ้าไม่พบค่า จะใช้ค่าเริ่มต้น **1.32** และแสดงคำเตือน

## การตั้งค่า

1. ใส่ connection string ใน `ConnectData()` ของ `Program.cs`
   > ไม่ควร commit รหัสผ่านจริงขึ้น GitHub ควรเก็บไว้ใน environment variable หรือไฟล์ config ที่ไม่ถูก commit
2. ตรวจชื่อคอลัมน์ที่เก็บค่าใน `M_LOV` (โค้ดใช้ `LOV_VALUE`) ให้ตรงกับฐานข้อมูลจริง
3. ถ้าต้องการรันเฉพาะบางคลัง ให้กำหนดค่า `targetWarehouseCode` (ค่า `null` = ทุกคลัง)

## วิธีรัน

```bash
# รันงานจริง (ต่อฐานข้อมูล)
dotnet run

# รัน Unit Test (ไม่ต่อฐานข้อมูล)
dotnet run -- --test
```

การรันงานจริงจะแสดงจำนวน KEEP / PENDING แยกตามเหตุผลและตามคลัง

## ผลลัพธ์

แต่ละ SKU ได้ข้อมูลตามนี้ (`SkuCleansingCandidate`): `HistoryMonths`, `ActiveMonths`, `Adi`, `Sd`, `CleansingStatus`, `CleansingMethod`, `CleansingReason`
รายการนี้เก็บในหน่วยความจำ เพื่อส่งต่อให้ PBI-04 (Keep Gate 2) โดย SKU ที่เป็น KEEP จะไม่ถูกตัดยอดในขั้นตอนถัดไป

> ขอบเขตของงานนี้ครอบคลุมถึงการคัดกรอง Gate 1 เท่านั้น การส่งต่อให้ PBI-04 และการบันทึกลงตารางสะอาด (PBI-08) ยังไม่ได้ทำในโปรเจกต์นี้
